# moonhop v001 hardware check (2026-11-19)

## Setup

- FreeWili 2 (`FREE-WILi2 FX0036`) on the on-board CMSIS-DAP probe, Windows.
- wilibsp pinned at `0a89c13`. `tools\dev run`, then `tools\dev` press / hold /
  release / screenshot, log from `tools\dev rtt`.

## Observed results

- Boot log: power zones requested `0x207`, `bmi323: chipid=0x1143 ok`,
  `codec: nau88c10 init done (16 kHz, speaker)`, `codec: speaker low power`,
  `moonhop: v001 up, imu=1 agentio=1`.
- RAM: 46.9 KB text + 323.5 KB bss (284 KB of it the framebuffer) of 512 KB SRAM.
- Calibration screen: title, prompts, live accelerometer, START over GREEN.
  Two injected GREEN presses started a game (right-tilt fell back to a board
  axis because nothing was tilted, as designed).
- Play screen: HUD SCORE / TIME / FUEL / ALTITUDE / HORIZ SPEED / VERT SPEED,
  jagged terrain, pads labelled 2X / 5X / 4X (1x unmarked), lander, THRUST over
  GRAY and EMERGENCY / TAP over RED.
- GRAY held: small flame drawn, fuel falling.
- RED held 2.6 s: large two-tone flame; log shows fuel 667 -> 580 over about
  2 s (about 4x the normal rate), then `flame=0` and fuel unchanged while red
  was still held - the 2 s burst limit works. The log shows the codec switched
  to the speaker for thrust and back to `speaker low power` once silent.
- Crashes: vector debris + `CRASHED`, fuel 1000 -> 700 -> 280 -> 0, respawn
  on the same terrain, then `GAME OVER` / `PRESS GREEN`; GREEN started a new
  game on new terrain.
- PAGE held: About screen with `moonhop`, `VERSION 001` and the repository
  link; release returned to the game. v001's first build kept simulating
  under the About screen; fixed by pausing while PAGE is held, re-checked
  (clock advanced only during the seconds outside the hold).
- Installed to `/apps/moonhop.uf2` with `tools\dev install`.
- `tools\dev test`: game-rule tests pass (terrain, pads, landings and crashes,
  scoring, fuel, 4x emergency burn, 2.5x force, burst limit, wrap, game over).

## Not verified

- **Sound was not heard** (no microphone check). Only the codec log lines
  confirm the speaker path switching on and off.
- **A safe landing on hardware** was not flown; only the host tests cover it.
- **Tilt steering with a real tilt**; only the no-tilt fallback ran.
- **LED colours** were not observed.
- HOME exit and launching from the board's own app list were not exercised
  for this app (both were for `lander`, with the same contract code).

## v002 (same day, after first play-test)

Player report: the NAV pad rotated the lander but turning the board did not;
GRAY thrust barely changed the descent rate.

- Cause of weak thrust: held buttons were read with a 300 ms freshness window,
  but the keyboard controller re-reports a held button about every 500 ms, so
  a physical hold produced pulsed thrust. Window raised to 1200 ms; normal
  thrust raised from 5.5 to 7.5 px/s^2 (about 3x gravity).
- Steering: turning the board while it lies flat does not change gravity, so
  the accelerometer could not see it. v002 also integrates the BMI323 gyro and
  learns from the "turn or tilt right" calibration gesture whether to steer by
  gyro turn (rotation about gravity) or by accelerometer tilt.
- Checked on hardware: new calibration screens; "TURNED 0 DEG" stays at 0 at
  rest (gyro bias removed); no gesture falls back to tilt (logged); GRAY held
  took vertical speed from +6 to -15 px/s in about 4 s at normal fuel burn.
- Not checked: steering with a real turn or tilt (needs a person), and a
  physical (not injected) GRAY hold - injected holds never went stale, so the
  freshness fix rests on the cadence documented in the keyboard driver.
- Installed v002 to `/apps/moonhop.uf2`.

## v004 (2026-11-19)

- Fallback steering axis (no clear setup gesture) changed from "board axis
  most perpendicular to gravity" (the top-to-bottom Y axis on this board) to
  the left-right X axis, so tipping the board toward or away from the player
  no longer rotates the lander. Gyro mode re-learns its resting offset while
  the board is still. Found while fixing the same bug in VoidPanzer.
- Checked on the board: no-gesture setup logged "steering by board X axis";
  lander angle and steering stayed 0. Not checked: a real tilt or turn.
